# 本地对账工作台 · Local Reconcile

**把银行流水和银行日记账，核对成一份有依据、能继续复核的结果。**

[![Windows checks](https://github.com/edcee314159/local-reconcile/actions/workflows/ci.yml/badge.svg)](https://github.com/edcee314159/local-reconcile/actions/workflows/ci.yml)

[English](README.en.md)

中文 Windows 桌面工具。核心流程本地运行，无需账号、API Key 或上传流水。自有代码采用 MIT 许可，打包依赖保留各自许可。

本地对账工作台是一款面向国内民营企业的财务对账与往来款核销工具，支持组合对账、差额分析、跨月未达、应收应付核销、多账户内部转账，以及退款冲销、预收预付款、红字退货折让、跨批次重复复核和客户供应商双方往来对账。当前版本 **0.7.0**。

[下载 Windows 便携包](https://github.com/edcee314159/local-reconcile/releases/latest) · 解压后运行 LocalReconcile.exe

## 证据链、合同阶段与更正模拟

- **业务证据链与缺失检查**：按单位、业务编号及应收/应付方向关联合同、订单、收货、验收、发票、收付款和退款。财务自行确认必需单据与合同，工具列出缺失、发票或资金超限、未核实资金等问题；只有检查通过后才能确认。支持红字发票，单据金额与实际银行证明分别列示。
- **合同分阶段结算**：依据明确合同登记首款、验收款、质保金等阶段，支持签约、到货、验收、开票、质保届满或自定日期加约定天数。条件由匹配业务单据和人工依据确认，未核实条件不推算到期日。逐阶段关联实际收付款与退回，显示剩余、逾期和提前收付。
- **账务更正影响模拟**：把改核销对象、撤销退款、红字抵减等动作加入队列，先看余额、账龄、对账状态和合同阶段的变化。任一步不通过，整份方案不应用；有关联退款等依赖时列出阻断项。应用前重新检查工作区和方案，成功后保留更正依据及事件审计。

进入「业务核算」→「虚构示例」→「证据链、合同阶段与更正模拟」即可体验。导入类别选择「业务凭证」，表格需要日期、金额、往来单位、单据编号、业务关联编号、单据类型及应收/应付方向。合同、付款、收款、退款金额为正；发票可正可负但不能为零；订单、收货、验收允许零金额。

凭证与银行的关联、合同阶段收付款属于证据核实层，与应收应付核销分别管理，不重复记账或自动过账。同一银行记录可同时作为这两种业务证明，每个证明层分别限制额度。截止日按所选工作期间月末计算；合同条件和天数由用户核实，工具不解释法律条款。后补单据只影响当前报告，既有月末快照保持不变。此处使用结构化 Excel/CSV，不识别扫描件，也不自动判断单据真实性。

新增报告保留证据汇总、原始单据、银行关联、合同汇总、阶段及更正审计；新功能工作区需要0.7.0或更新版本。旧工作区继续可读。

## 先体验，再导入自己的表

项目提供开源代码和内置虚构示例。源码启动方法见下方；Windows 便携包解压后运行 LocalReconcile.exe，无需安装 Python。

1. 点击「使用虚构示例」。
2. 看清双方字段与金额方向，再勾选确认。
3. 点击「开始核对」，选择候选查看原始行与核对依据。
4. 对核实过的关系确认或拒绝，保存项目，或导出 Excel。

示例同时展示正常逐笔、同额多笔、金额差异和双方单边记录。内置示例全部为虚构数据，不需要真实财务数据就能体验。

## 从源码启动

适用于 Windows x64，需安装 Python 3.12。下载或克隆仓库后，在仓库根目录打开 PowerShell，执行：

    py -3.12 -m venv D:\Codex\local-reconcile\user-environment
    $env:PIP_CACHE_DIR = 'D:\Codex\local-reconcile\user-cache'
    D:\Codex\local-reconcile\user-environment\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
    $env:PYTHONPATH = Join-Path (Get-Location) 'src'
    D:\Codex\local-reconcile\user-environment\Scripts\python.exe -B -m local_reconcile

首次安装依赖需要联网，完成后应用核心流程本地运行。若 D 盘不可用，可将这些环境与缓存路径改为源码目录之外的可写位置。再次运行只需执行最后两行。

## 能做什么

- 读取 .xlsx 和 UTF-8 / UTF-8 BOM .csv；选择工作表、表头行及字段。
- 确认单金额列的正负方向，或使用收入、支出双列。
- 按共同业务编号、金额、日期和交易对方形成候选，显示规则依据。
- 对同额多笔保留歧义；编号冲突不通过放宽规则强行对平。
- 确认、拒绝、撤销、手工指定一对一，保留操作记录。
- 保存包含输入快照的 .lrproj，重开后继续复核。
- 导出八张工作表，保留原始明细、来源行、参数与人工状态。

**候选不等于已确认。** 批量确认只接受无冲突、无歧义的共同编号强依据候选，确认前展示数量和净额。

## 业务核算能力

点击左侧「03 业务核算」，进入新增工作台。原有逐笔流程和旧项目仍可使用。

- **组合对账**：自动寻找一对多、多对一和多对多的等额组合，每侧最多5笔；手工组合每侧最多100笔。保留歧义，确认前查看原始行。
- **差额分析**：记录手续费、折扣、退款等差额类别与结算依据；差额已说明不会被当作等额相符。
- **跨月未达**：生成月末未达及往来余额快照，进入下一期间继续处理，历史快照保持当时状态。
- **应收应付核销**：导入每张单据一行的应收/应付明细，支持部分核销与撤销，检查收付款可用余额和单据未结清余额。
- **多账户内部转账**：登记本企业人民币账户，核对转出和转入；有依据的手续费单列，内部转账不能再次用于往来核销。

- **退款、冲销与退票**：关联实际反方向银行流水与原收付款，支持部分退款；退款可关联原核销并恢复单据余额，或减少尚未核销的预收预付款余额。
- **预收预付款**：登记明确往来单位的预收/预付资金，预留银行可用金额；后续按同一单位、对应方向的单据分次核销，展示未使用余额。

业务页的「虚构示例」包含全部能力。工作区使用 .lrwork（格式版本 2），包含未加密来源快照和操作历史；可验证导入旧版 .lrproj 并另存，原项目不被覆盖。

自动组合默认组内跨度 7 天，可在产生业务操作前调整为 0—31 天；搜索预算覆盖候选池构建及组合枚举；自动池超过 16 条或达到搜索预算时显示范围受限，不能把“未搜索完成”当作“没有匹配”。自动多对多采用共同编号，或同一交易对方且非空编号不冲突的记录组；依据不足时需人工核实组合。外币换算与收支混合净额组合暂不支持。已结账期间的补录需要另建修订工作区。跨月在途只表示尚待核实，不自动生成调账分录。

银行、日记账沿用日期/金额/对方/共同编号字段映射；应收应付必须提供日期、正数单据金额、往来单位及唯一单据编号，可选到期日。银行业务编号和发票编号不是默认相同的编号体系，往来核销需结合业务资料人工确认。

业务报告包括已确认关系、组成明细、待确认候选、搜索受限范围、差额说明、未达、期间快照、核销与余额、内部转账、退款冲销、预收预付余额、原始记录及操作历史。原始金额不被改写，不连接或修改企业账簿。


## 银行余额调节表与往来账龄

- **银行余额调节表**：在业务核算页选择账户，录入银行对账单和账簿的期末余额及依据；逐笔核实未达分类后计算调节后余额。银行余额加企业已收银行未收、减企业已付银行未付；账面余额加银行已收企业未收、减银行已付企业未付。
- **复核状态**：没有期末余额时不推算余额；待查、未分类项目不计入调整，并保留待复核提示。差额为零且无待复核项目时显示“调节后相符”。余额与分类均不自动过账。
- **账龄与逾期**：按客户/供应商、应收/应付分别汇总净未结清余额，账龄分为0—30、31—60、61—90、90天以上，按单据日期计算；逾期按到期日计算，到期当天不计为逾期，没有到期日的金额单独列示。支持单位搜索、应收应付筛选及仅逾期筛选。
- **历史与导出**：生成月末快照时保留余额调节表、结账时的账户范围和账龄分析；之后核销、退款或登记新账户不改写旧月末报表。新期间必须重新录入余额。导出报告增加余额调节表、调节明细、账龄汇总及账龄明细，可用于催收与付款核查。

点击「虚构示例」可选择“月末余额调节与逾期分析”，体验四类未达、调节后相符、逾期应收及缺到期日应付。所有记录均为虚构。老工作区继续可读；新增余额调节或月末账户范围事件需使用0.4.0或更新版本。

## 退款及预收预付操作

1. 导入原银行收付款、实际反向退款流水及相关应收应付单据，核实日期和收付方向。
2. 在「退款与冲销」页选择原收付款、反向流水及金额。已核销款项选择对应原核销记录；未核销预收预付款选择其登记；原款项未分配时选择“尚未分配部分”。填写回单或业务依据后确认。
3. 在「预收预付款」页登记原银行收付款的全部或部分可用金额，再选择登记和后续单据进行核销。核销须同一往来单位、收付方向对应，单据日期不早于原收付款。
4. 余额、退款关联及原始行可在界面和导出报告中检查。预收预付核销记录统一列在「应收应付核销」页，撤销退款或登记需先处理依赖关系。

退款/冲销/退票功能记录实际资金反转及其核销影响，不自动作废发票、不自动生成红字凭证或财务分录。单笔退款不能超过反向流水余额及指定来源的可退余额；涉及多次核销时按原核销逐项登记。撤销操作同样检查后续占用，不能造成单据超额核销。旧版 `.lrwork` 可继续打开，包含新增业务事件的工作区需使用 0.3.0 或更新版本。

## 红字退货、重复检查与双方往来对账

- **红字、退货与折让**：导入应收或应付方向的红字/退货折让明细，金额可正可负，系统以绝对金额作为可用抵减额度，原始内容完整保留。按同一单位、对应方向选择原单据，填写依据后分次抵减；抵减不能超过红字额度及原单据余额。资金净核销、红字抵减和未结清余额分别列示。
- **已收付款项退货**：先在「退款与冲销」页关联实际银行退款及原核销，恢复相应单据余额，再抵减。红字抵减本身不表示已退款，不自动开具红字发票或生成会计分录。撤销会检查后续占用，不能使单据超额结清。
- **跨文件、跨批次重复检查**：不同批次的银行/日记账记录，按账户、单位、金额、编号或缺编号时的同日条件分组提示。待复核来源不能继续确认对账、核销、登记预收预付、关联退款、转账或未达分类。核实后填写依据，确认为独立业务，或排除确属重复的来源行；排除保留原始内容。新增来源改变重复组时需重新复核。仅凭同额不自动删除，不保证发现所有重复业务。
- **客户与供应商双方对账**：导入「客户对账单（我方应收口径）」或「供应商对账单（我方应付口径）」，每个批次只含一个单位，每张单据一行非负未结余额，可包含零余额。日期为原单据日期；登记本期月末截止日及来源依据后，按同一单位与完全一致的单据编号比较双方余额。
- **逐笔核实与历史保留**：区分金额一致、金额差异、仅本企业有、仅对方有。缺单单独显示；总额相同不能代替逐笔确认。金额一致才可确认，差异说明仍保留未核平状态。后续核销、退款或红字抵减改变余额时，原确认提示重新复核。每个月导入对应月末新对账单，余额未变化的相同文件也可在新月份导入；历史快照保持当时状态。

「虚构示例」中的“红字退货、重复检查与双方往来对账”可直接体验三项业务。导出增加红字抵减、红字可用余额、疑似重复交易、双方往来对账汇总和明细。新业务事件需使用 **0.5.0 或更新版本**读取，旧工作区继续可读。

## 净到账还原与月末核算检查

点击「03 业务核算」，新增「平台净到账核对」和「月末归属与跨期核对」两页。虚构示例中选择“净到账还原与月末核算检查”可直接体验。

### 订单与结算构成

导入「结算原订单」「结算组成明细」和银行流水。原订单为每单一行正数金额；结算组成每行须有唯一行号、结算批次、类别和金额，销售/退款还须有原订单号。平台/单位名称和订单号必须完全一致。

- 销售、其他加款为正；退款、佣金、运费、其他扣款为负。系统按来源组成计算应到账，保留每项来源，不根据差额猜测费用。
- 累计销售结算不能超过原订单金额，累计退款不能超过已结算销售。缺原订单、超结算或超退款时列出待核实问题，阻止确认。允许分批结算和净支出结算；全额抵消后净额为零且无实际资金往来时，可留空银行并填写依据确认。
- 选择同一本企业人民币银行账户的1—100笔流水并填写依据，净额完全一致才可确认。同一银行来源不能由两个结算批次重复确认；此功能确认结算证明，不自动生成收入、费用分录或往来款核销。
- 新增组成或原订单依据改变后需要重新复核；排除再恢复来源也不能让旧确认自动生效。撤销关联确认后才可排除已占用来源。

示例：销售100元−退款5元−佣金2元−运费1元＝应到账92元，与银行92元逐项核对。

### 核算归属与遗漏检查

分别导入「待核算业务（收货/验收/服务）」和「实际记账明细（凭证行）」。业务基础每个单位/业务编号一行正数金额；记账明细按业务编号关联，并提供凭证行唯一编号，冲销用负数。日期分别为业务发生日和实际记账日期，金额须采用财务确认的一致口径，银行日记账不作为费用已入账的替代证据。

1. 在业务页登记已核实的归属规则及依据：一次归属使用业务发生日；按月平均分配到范围内月份，分的尾差优先分到前面月份；按日分配使用实际天数，月末累计整数分计算，合计与原金额严格一致。
2. 逐笔比较本期应归属、本期已记账、本期差异和前期累计差异。没有规则显示“未确认”；找不到业务基础的凭证单独显示；未来记账不计入当前月份。
3. 开票/收付款月份在归属范围外、少记、多记、前期归属差异或累计记账为负均提示核实。差异说明保留待复核状态，不替代补录与账务处理；来源或规则变化后说明失效，需要重新核实。
4. 月末保留当时检查报告。新收到的历史业务、结算证据和记账明细可在当前期间导入，显示当前及前期差异，不重写已保存月末报告。

规则是财务人员确认的业务核算口径，不自动判断适用会计政策、税额或生成会计分录。按月/按日方法是可选分配工具，应按实际业务选择；归属范围最多1200个月。

导出增加「净到账还原汇总」「结算组成明细」「结算订单核验」「结算到账流水」「月末核算检查」「核算记账依据」六张表，保留当前及历史结果。含新增事件或扩展字段的工作区需使用0.6.0或更新版本；旧工作区继续可读。

## 输入要求

一次核对同一个人民币银行账户，两份文件分别为银行流水和对应的银行日记账。日期与金额必需，摘要、交易对方与共同业务编号可选。

单金额列统一成「收入正、支出负」。不同软件的“借/贷”口径可能不同，请看方向预览后确认。银行流水号和企业凭证号不默认视为共同业务编号。

账号与币种可来自列或由用户声明，报告区分声明与文件核验。金额、日期解析错误会阻止正式核对，不静默跳过。文本型编号的前导零保留；数字单元格已经丢失的长编号精度无法恢复。

支持明确的年月日；日/月顺序不明确时须选择格式。共同编号匹配可设置 0—31 天日期容差，默认 0 天。普通、弱依据候选只处理同日记录。

首版上限：每份文件 25 MiB、100,000 行、200 列；项目 100 MiB。扫描件、PDF、OFD、旧版 .xls、外币、跨账户账面匹配暂不支持；多账户间调拨通过业务核算页单独确认。

## 导出内容

核对总览、已确认关系、待确认候选、歧义与未匹配、银行原始明细、日记账原始明细、输入检查、参数与操作记录。

金额运算使用整数分。报告统计值预先计算，候选不重复计入已确认金额。超过 Excel 可安全表示精度的金额以文本保留。原始文本按字符串写入，不执行源文件中的公式、宏或外部链接。

## 本地数据

原始输入不被覆盖。项目文件包含财务明细快照且未加密，请选择适合的本地保存位置。应用不主动上传数据、不内置遥测或自动更新请求。

请勿把真实流水、账号、密钥或 .lrproj 项目提交到公开仓库。反馈问题优先用内置示例、虚构数据或经授权的脱敏案例。

## 开发与验证

需要 Windows 10 1809+ / Windows 11 x64、Python 3.12。创建独立环境，从 requirements-dev.lock 安装固定依赖：

    python -m pip install --require-hashes -r requirements-dev.lock

验证源码与打包命令（用实际绝对路径替换参数）：

    powershell -File scripts/verify.ps1 -PythonPath <独立环境的python.exe> -OutputRoot <源码之外的测试目录>
    powershell -File scripts/build_windows.ps1 -PythonPath <独立环境的python.exe> -OutputRoot <源码之外的构建目录>

构建脚本自动检查源码、收集第三方许可及对应 Qt 源码、打包并验证发行内容。自行构建出的便携包包含解释器、Qt 和运行组件，使用者无需另装 Python；便携包通过构建脚本生成。third_party/SOURCE_INFO.md 说明重建与替换库的方法。

基准与真实演示由 scripts/benchmark.py、scripts/capture_demo.py 在外部输出目录生成；请写明运行配置，不把合成数据成绩宣称为真实业务准确率。
